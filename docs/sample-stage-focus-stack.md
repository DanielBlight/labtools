# Sample stage and multiple Z focuses

Baseline: a3d279638f087e2083a473101226c111663dfb0c (clean main snapshot supplied 2026-11-25).

## Stage popup
Stage sits beside Camera/Mirror and uses the existing Labtools stylesheet and cards, not DAISY styling. X=0, Z=1, Y=2 in Python (DAISY axes 1,2,3). Native USB uses the existing pylablib Attocube.ANC350() connection. No connection or sample movement occurs merely by opening the popup. All USB construction, commands, readback and close run on one persistent worker thread. Simulation uses an explicit synthetic stage and never falls back from USB errors.

Controls: Connect/Disconnect, explicit Refresh readback, Stop, per-axis position/status, absolute/relative target in micrometres, Single step -/+, DC offset and Ramp to zero, step amplitude/frequency, output enable and ramp-zero/disable. The popup reflows from three axis cards to one column at narrow widths. Readback is refreshed after commands or explicitly, not continuously polled. LUTs, sensor voltage, target tolerances, triggers, quadrature and other advanced settings are not written. Continuous/endless travel, capacitance measurement and error reset are not exposed in this first implementation. Existing controller configuration is preserved on connection; the screenshot's amplitude/frequency values are editor defaults only until actual readback, never automatic writes.

DC is restricted to 0-60 V. Each nontrivial ramp uses 50 updates with a total requested wait of 0.5 s, plus USB overhead. Step amplitude is limited to 0-60 V; the frequency editor is limited to 1-2000 Hz. A manual single step ramps that axis to zero first, issues exactly one signed step and leaves DC at zero. Absolute/relative moves also ramp DC to zero first, have a 30 s timeout and send Stop on completion/error/cancellation. These controls are not sample/objective clearance interlocks. +/- mean controller directions; no assumption is made about towards/away from the objective. Native end-of-travel and sensor status are checked. Stop is cooperative; a completed step cannot be undone and a blocked USB call must return before cleanup can continue.

Output disable ramps to zero before grounding. Enabling a previously disabled output starts at zero and ramps to its stored DC target. Connect, Disconnect and ordinary popup close do not automatically ramp, ground, step, enable outputs or change laser output. Closing the main application waits for active work, then closes the USB connection. DAISY must not simultaneously own the controller.

## Multiple Z focuses
Enable the checkbox in the intensity-map panel. Enter a comma-separated voltage list (each 0-60 V) in acquisition order. Sweeps=1 means no coarse extension. For more sweeps, the application ramps Z to zero, takes the selected number of signed single steps using the controller's existing amplitude/frequency, then repeats the voltage list. This process is named Coarse extension, not a voltage above 60 V. One step is not assumed to equal a 60 V DC sweep; neighbouring sweeps can overlap or have gaps. Positions/readbacks and coarse-step history are recorded instead of inventing a calibrated extended voltage.

Open Stage and explicitly Connect before starting a focus stack. Enable the required axis output explicitly if disabled. Use a small map first, confirm the signed step direction and clearance, and use small focus lists while testing. A stack reserves the stage for the entire acquisition and uses the map's existing optical lease. Manual sample motion reserves the workspace optical path, excluding map/spectrum/annealing activity. Stop all and main-window close use the existing cooperative worker lifecycle.

All maps use the same snapshotted XY/counting settings. The cyclic IDQ counting repair is untouched. Stage DC ramps and an additional configurable Z settling delay precede each map. Progress identifies sweep and DC level. On completion, a retained-map selector browses the maps, optionally using one common colour scale; explicit manual colour limits take precedence. No automatic best-focus selection or pixel filtering is applied. The synthetic stage exercises mechanics and workflow only; simulation maps are not a calibrated optical focus model.

Completion, Stop and failure hold the last applied stage offset; no automatic return or compensating coarse step is performed. Completed maps and deliberately stopped partial maps retain their raw counts. If an acquisition raises, earlier completed maps and the latest active-map progress remain retained. Save before a new acquisition or closing: RAM retention is not durable.

With map saving enabled, each level has its ordinary map outputs beneath a unique focus-stack folder, and the final retained stack has run.json + arrays.npz (allow_pickle=False). With saving disabled, no stack files are written; the existing Save results button exports the complete retained stack afterward. Single-map checkpoint resume is refused for focus stacks; whole-stack resume is not implemented. Focus settings are included in existing workspace display preferences/settings; loading settings never moves hardware.

## Validation and remaining acceptance
142 offline tests passed, including 39 new stage/focus tests. The Qt test module was skipped because PyQt6 is unavailable in the build environment. Tests ran with --noconftest to avoid the repository's autouse Qt fixture. Syntax and a basic unused-import scan passed; Ruff, actual Windows GUI rendering and connected USB acceptance remain pending. No real endpoint was contacted. Existing pylablib-lightweight/PyUSB project dependencies are used; no dependency or lockfile change is included.

References consulted: user-provided ancFunctions.py and ANC350 manual, and the pylablib ANC350 API source at https://pylablib.readthedocs.io/en/latest/_modules/pylablib/devices/Attocube/anc350.html .
