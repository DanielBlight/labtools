# LabTools 0.2.0-rc.1 release candidate

## Historical candidate record

Status: candidate-specific evidence. The baseline and limitations below describe
this candidate's original record, not a fresh validation of later source changes.
For current capability and remaining gates use [current state](../current-state.md)
and [release plan](../release-plan.md). Analysis, notebooks and Napari extras now
exist; instrument/GUI optionality remains future work. No new candidate is approved
by the 2026-11-22 alignment repair.


## Intended use

This candidate prepares LabTools for a controlled internal laboratory pilot. It is not
an unrestricted release and does not by itself approve connected-hardware operation.

## Candidate scope

- unified operator workspace
- simulated intensity mapping and spectroscopy
- camera preview, simulation, annotations and dark correction
- versioned measurement recipes and dispatch
- workflow ownership, cancellation and close refusal
- package and repository release-engineering baseline

Real spectroscopy, camera, mirror, SourceMeter and Annealing workflows remain
conditional on the acceptance matrix in `docs/release-plan.md`.

## Validated baseline

- Windows
- Python 3.12.6
- 1,206 non-hardware tests passed
- Ruff validation over active source and tests
- locked environment through `uv.lock`

## Installation candidate procedure

```powershell
uv sync --frozen --group dev
uv run pytest -q -ra -m "not hardware"
uv build
```

Install the wheel into a fresh environment before lab-PC acceptance. Do not operate
from the development checkout as the final deployment method.

## Known limitations

- connected tests are not yet comprehensively marked by subsystem
- physical device acceptance is incomplete
- licence and third-party notice decisions are outstanding
- optional runtime dependency groups have not yet been separated
- expected Qt offscreen warnings remain in automated GUI tests
- Laser Annealing is independently gated

## Required evidence before pilot approval

1. Windows CI passes for the candidate commit.
2. Wheel installs and launches in a fresh environment.
3. Supported device rows in the hardware matrix are complete.
4. Side-by-side lab-PC installation and rollback are demonstrated.
5. Supported and excluded workflows are recorded in the release decision.
