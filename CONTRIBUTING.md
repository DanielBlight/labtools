# Contributing

Read [Architecture](docs/architecture.md) and [Development](docs/development.md).
Use a separate branch, keep behaviour changes distinct from structural cleanup,
and run the offline tests before proposing changes. Never run hardware scripts
or integration tests as an automatic development step.

Keep the README short. Put detailed instrument procedures in the hardware
reference, simulation details in its guide, and launch commands in the command
guide. Update compatibility notes when moving modules or changing entry points.
